# Week 7 observation

> Task 2는 노트북(i5-12450H)의 Linux VM에서 측정했고, Task 1·3은 클라우드(Linux, Python 3.13)에서 돌렸다. Task 1·3의 결과(SSE, 거리 계산 횟수)는 시드가 고정되어 머신과 무관하다.

## Task 1
- R3: 빈 클러스터는 **이전 중심점을 유지**했다(40번 중 3번 발생). 대안인 "자기 중심점에서 가장 먼 점으로 이동"으로 바꾸면 랜덤 초기화 성공이 24 → 27번으로 늘지만, 결과가 이상치 하나에 좌우된다.
- 랜덤 초기화는 40개 시드 중 **24번(60%)**만 세 덩어리를 찾았고(SSE 0.12), 나머지는 두 덩어리를 한 중심이 맡아 SSE ≈ 96이었다. k-means++는 **40/40**, 평균 SSE 0.120 대 38.513이다.
- ++의 초기화 비용은 n·k = 27번(반복 한 번 분량)이고, 그 대가로 나쁜 지역 최적을 피한다. 다만 중심을 하나 고를 때마다 데이터를 한 번 훑어야 해서 디스크에 있는 큰 데이터면 k번 더 읽어야 하고, D² 가중치 때문에 이상치에 끌린다. 그럴 때는 표본으로 초기화하는 편이 낫다.
- SSE는 k = 1 → 9에서 256.1, 96.1, **0.12**, 0.09, …, 0으로 계속 준다. 최소화하면 언제나 k = n(SSE 0)이 답이므로 k는 값이 아니라 꺾이는 곳(k = 3)으로 고른다.

## Task 2
- 점 1,000개·쌍 20,000개에서 contrast는 **d ≈ 50에서 1 아래**(d = 40: 1.31, 50: 0.98), d ≈ 120에서 0.5 아래, d = 1000에서 0.15였다. 평균 거리는 √(d/6), rel. sd는 0.59/√d와 d ≥ 10부터 맞았다.
- A6: d = 50 고정에서 n = 20 → 50,000이면 contrast가 0.58 → 1.13, 같은 n에서 쌍을 10배 뽑으면 1.05 → 1.38로 커졌다. rel. sd는 0.08대로 그대로였다. 저주의 크기는 d가 정하고, 그것이 얼마나 아픈지(극단값의 간격)는 비교하는 쌍의 수가 정한다.
- A8: 3주차 LSH는 위협받지 않는다. shingle 집합은 독립·균등한 좌표가 아니고, 무관한 쌍이 Jaccard 0 근처에 몰리는 것은 오히려 near-duplicate를 S-곡선으로 골라 내기 쉽게 만든다. MinHash 일치 확률 = Jaccard라는 성질도 차원과 무관하다.

## Task 3
- Elkan 방식을 썼다. 점마다 상한 u 1개와 **중심점별 하한 L 12개**, 즉 라벨 외에 **13개의 수**를 저장한다(20,000 × 13). 반복마다 중심점 쌍 거리 66번과 이동 거리 12번을 더 잰다(총 3,276번, 전체의 0.8%).
- R5: 일을 가장 많이 하는 것은 **중심점별 하한 L[i][j]**다. 2회차 이후 (점, 중심점) 후보 924만 개 중 615만 개(67%)를 `u ≤ L[i][j]`가 지웠고, 점 전체를 건너뛰는 `u ≤ s(a)` 검사는 점-반복의 26%만 처리했다. 대가는 n·k 메모리와 반복마다 n·k번의 뺄셈(거리 계산 0번)이다. 하한을 2개만 두는 Hamerly 방식은 88.9%에 그쳤다.
- 거리 계산 10,320,000 → **398,366 (96.1% 감소)**, SSE 차이는 **정확히 0**이고 라벨·중심점도 기준선과 비트 단위로 같다. 근사가 아니라 "바뀔 수 없다고 증명된 거리"만 건너뛰므로 매 반복의 배정이 같고, 같은 배정이면 `_means`가 같은 중심점을 낸다.
- 첫 반복은 아무 경계도 없어 n·k = 240,000번을 다 잰다. 이것이 전체 398,366번의 **60.2%**다. 남은 42번의 반복은 합쳐서 158,366번(반복당 평균 약 3,800번, 기준선은 240,000번)이다.
