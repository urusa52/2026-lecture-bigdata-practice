# Week 5 observation

## Task 1
- dead end의 rank를 모든 페이지에 균등하게 나눠주는 방식을 골랐다. 교재처럼 dead end를 지우고 계산하면, PDF처럼 링크는 없지만 중요한 페이지가 계산에서 빠지기 때문이다. 다만 실제 사람은 막다른 페이지에서 뒤로 가기를 누르지 아무 페이지로나 가지 않으므로 현실과 다르다. 또 dead end가 많으면 rank가 골고루 퍼져서 순위 차이가 줄어드는 한계가 있다.
- 순간이동이 있으면 어느 페이지에서든 다른 모든 페이지로 갈 수 있게 된다. 그래서 rank가 밖으로 새지도 않고(dead end), 한곳에 갇히지도 않는다(spider trap). 하나의 수정으로 두 문제가 같이 풀리는 이유다.
- β는 surfer가 지금 페이지의 링크를 클릭할 확률이고, 1−β는 지루해져서 아무 페이지로나 순간이동할 확률이다. β = 0.85면 평균 5~6번 클릭한 뒤 순간이동한다(처음엔 8~9번으로 예상했다). 실제 클릭을 세는 게 아니라 링크 구조만으로 계산하는 모델이라, 사이트의 주제나 신뢰도는 반영하지 못한다.

## Task 2
- β가 0.5 → 0.85 → 0.99로 커지자 반복 횟수는 14 → 20 → 24로 늘었다. 순간이동이 줄면 점수가 골고루 섞이는 데 시간이 더 걸리기 때문이다. 다만 생각보다 조금 늘었다. 링크가 허브에 몰린 그래프라 대부분의 페이지가 몇 번만 클릭하면 허브에 닿아서, 점수가 빨리 섞이기 때문으로 보인다.
- (A4) 노드를 1,200개에서 20,000개로(간선 17배) 늘리면 반복 횟수와 시간이 둘 다 17배 넘게 늘 거라고 예상했다. 시간은 약 16배로 간선 수만큼 늘었지만, 반복 횟수는 20 → 21로 거의 그대로였다. 가지만 늘었을 뿐 허브 중심이라는 모양은 그대로라서다. 반복 횟수는 그래프의 모양이, 시간은 크기가 정한다.
- (A6) top-10에 드는 페이지는 β를 바꿔도 같았다. 점수 차가 0.0006뿐인 7위와 8위만 β 0.50~0.55 사이에서 순서가 바뀌었다. 그래서 공개된 순위에서 1~2위는 믿을 만하지만, 점수가 비슷한 중후반 순위는 순위를 낸 사람이 고른 β에 따라 달라질 수 있다.

## Task 3
- 행렬 M 대신 인접 리스트(정수 m개)와 rank 벡터 두 개(float 2n개)만 저장했다. float 기준으로 n² = 1,440,000개가 2n = 2,400개로 줄었다. 결과는 메모리 600배, 속도 77배(strong)다.
- (R5) 순간이동 몫은 점수 합이 항상 1이라서, 점수가 어떻든 모든 페이지가 같은 값 (1−β)/n을 받는다. 그래서 n×n 행렬 없이 반복마다 숫자 하나를 계산해 모든 페이지에 더하면 된다. dead end 몫도 똑같이 숫자 하나로 처리된다.
- dense 결과와의 최대 차이는 1.17e-15다. 더하는 순서가 달라서 생기는 부동소수점 반올림 오차라 버그가 아니다.
